# 날씨 시각화 구름 시스템 개선 작업 문서

## 개요
이 문서는 3D 날씨 시각화 프로젝트의 구름 렌더링 시스템 개선 작업을 정리한 것입니다.

## 문제점
1. 구름이 날씨 상태와 관계없이 흰색으로만 표시되는 문제
2. 복잡한 코드 구조로 인한 디버깅의 어려움
3. 날씨별 구름 색상 차별화가 부자연스러움

## 해결 과정

대규모 `WeatherVisualization.tsx` 파일을 모듈화하여 유지보수성 향상:

### 2단계: 구름 색상 문제 해결

#### 문제 원인 분석:
1. deck.gl ScatterplotLayer의 색상 적용 방식 이해 부족
2. 알파 블렌딩 파라미터 설정 오류
3. 레이어 opacity와 개별 파티클 알파값의 중복 적용

#### 해결 방법:
1. **알파값 계산 수정**
   ```typescript
   // 변경 전
   getFillColor: (d) => [d.color[0], d.color[1], d.color[2], Math.floor(d.opacity * 180)]
   
   // 변경 후
   getFillColor: (d) => {
     const alpha = Math.floor(d.opacity * 255); // 정확한 0-255 범위 변환
     return [d.color[0], d.color[1], d.color[2], alpha];
   }
   ```

2. **블렌딩 파라미터 간소화**
   ```typescript
   // 복잡한 WebGL 파라미터 제거
   parameters: {
     depthTest: false  // 기본 블렌딩 사용
   }
   ```

3. **레이어 투명도 조정**
   ```typescript
   opacity: 1  // 개별 알파값만 사용하도록 설정
   ```

### 3단계: 구름 시스템 재설계

#### 사용자 피드백:
"날씨별로 구름의 색이 바뀔 필요는 없습니다. 날씨에 따라서는 구름의 양만 바뀌면 됩니다."

#### 구현 내용:

1. **일관된 구름 색상**
   - 모든 날씨 상태에서 동일한 회색 구름: `[220, 220, 230]`
   - 투명도만 날씨별로 미세 조정 (0.5 ~ 0.8)

2. **날씨별 구름 밀도 시스템**
   ```typescript
   // 구름 클러스터 수 계산
   const clusterCount = Math.floor(cloudDensity * 10) + 1;
   
   // 클러스터당 파티클 수
   const particlesPerCluster = Math.floor(cloudDensity * 20) + 5;
   ```

   | 날씨 상태 | Cloud Coverage | 클러스터 수 | 파티클/클러스터 | 총 파티클 |
   |----------|----------------|------------|----------------|----------|
   | 맑음      | 0-20%         | 1-3개      | 5-9개          | 5-27개   |
   | 구름조금   | 20-50%        | 3-6개      | 9-15개         | 27-90개  |
   | 흐림      | 50-75%        | 6-8개      | 15-20개        | 90-160개 |
   | 비        | 75-90%        | 8-10개     | 20-23개        | 160-230개|
   | 폭우      | 90-100%       | 10-11개    | 23-25개        | 230-275개|

3. **파티클 속성 조정**
   - 색상 변화 범위 축소: 0.9-1.1 (기존 0.8-1.2)
   - 투명도 범위 조정: 최대 0.6 (기존 0.8)
   - 크기 변화는 유지하여 자연스러운 구름 형태
